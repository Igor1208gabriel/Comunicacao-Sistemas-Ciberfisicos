\chapter{Especificação funcional do sistema}
Esta seção apresenta a descrição funcional do sistema robótico Robinho, incluindo seus objetivos, modo de operação, componentes principais e requisitos. O capítulo estabelece a base conceitual necessária para a modelagem arquitetural apresentada nos capítulos seguintes.

\section{Visão geral do sistema}
O Robinho é um robô móvel com direção diferencial, composto por motores de tração independentes e uma estrutura leve. A plataforma foi projetada como um ambiente de experimentação para testes de algoritmos de visão computacional, integração de sensores e validação de arquiteturas distribuídas em sistemas Ciberfísicos.

Robinho é desenhado como uma plataforma autônoma e distribuida que emprega diversos componentes de \textit{software} para permitir percepção, tomada de decisões e atuação em tempo real. Sua infraestrutura é construida para garantir comunicação eficiente, escalabilidade de robustez em ambientes dinâmicos.

\section{Objetivo funcional}
O sistema foi projetado para:

\begin{itemize}
    \item capturar imagens em tempo real
    \item processá-las por meio de algoritmos de visão computacional 
    \item identificar um alvo 
    \item gerar comandos de velocidade para os motores 
    \item deslocar-se, ajustando sua trajetória
\end{itemize}

Esta funcionalidade representa apenas uma instância possível dentro do conjunto de aplicações que o sistema pode suportar, dada sua arquitetura extensível.

\section{Arquitetura física}

Robinho consiste dos seguintes componentes de \textit{hardware}: 
\begin{itemize}
    \item \textbf{Raspberry Pi 2B} - A unidade de processamento principal, responsável por executar o ambiente ROS2.
    \item \textbf{ESP-Cam} - Um microcontrolador equipado com um módulo de câmera, responsável por transmitir o vídeo para o Raspberry Pi.
    \item \textbf{Driver de motor Ponte L298N} - Controla o movimento de ambos os motores.
    \item \textbf{Motores DC e chassis de direção diferencial} - Fornecem mobilidade ao sistema.
    \item \textbf{Mouse, Teclado e Monitor}, para interface com o sistema
\end{itemize}

\section{Arquitetura lógica}

O \textit{software} do sistema é majoritariamente construido com o ROS2 em Python, visando flexibilidade e modularidade. O \textit{sketch} executado no ESP-CAM é escrito em C++.

Os componentes de \textit{software} incluem:
\begin{itemize}
    \item \textbf{Módulo ESP-Cam} - O módulo do ESP-Cam lê a entrada da câmera, processa a imagem e envia para o Raspberry Pi.
    \item \textbf{Nó de Comunicação com ESP} - Nó ROS responsável por capturar o input do ESP-Cam e encaminhar para mais processamentos de imagem.
    \item \textbf{Nós de visão computacional} - Um conjunto de nós que processam a tranmissão de vídeo e aplica algoritmos de visão computacional a fim de extrair dados relevantes.
    \item \textbf{Nó de controle do Motor} - Nó responsável por interpretar o resultado dos algoritmos de visão computacional e gerar comandos de velocidade para os motores.
\end{itemize}
Estes componentes realizam trocas de mensagens seguindo um caminho de comunicação específico, com tipagem de mensagens bem definidas. Uma representação deste fluxo é apresentada no próximo capítulo por meio de diagramas de modelos.

\section{Requisitos Funcionais}

O sistema deve:
\begin{itemize}
    \item RF01 — Capturar imagens do ambiente por meio da ESP-CAM.
    \item RF02 — Transmitir quadros para o Raspberry Pi de forma contínua.
    \item RF03 — Processar a imagem para extrair o elemento alvo (círculo branco).
    \item RF04 — Calcular a posição do alvo em relação ao centro da imagem.
    \item RF05 — Gerar comandos de controle para ajustar a trajetória do robô.
    \item RF06 — Encaminhar os comandos à ponte H L298N via GPIO.
    \item RF07 — Mover o robô de forma contínua enquanto o alvo é detectado.
\end{itemize}




\section{Requisitos Não Funcionais}

\begin{itemize}
    \item RNF01 — Baixa latência:O fluxo completo (captura → processamento → controle) deve operar em tempo hábil para permitir reação adequada a alterações do alvo.
    \item RNF02 — Modularidade:O sistema deve suportar substituição ou inclusão de algoritmos de visão sem alterar sua estrutura geral.
    \item RNF03 — Escalabilidade:A arquitetura deve permitir expansão futura com novos sensores ou módulos de software.
    \item RNF04 — Estabilidade: A comunicação entre ESP32-CAM e Raspberry Pi deve permanecer funcional mesmo com variações na taxa de quadros.
    \item RNF05 — Transparência da arquitetura: Cada componente deve ter responsabilidades claramente definidas, facilitando a modelagem em AADL.
\end{itemize}



\section{Operação do Sistema}
O sistema opera em um laço contínuo, onde:
\begin{enumerate}
    \item O ESP-CAM captura um frame de vídeo.
    \item A imagem é enviada ao Raspberry Pi.
    \item O pipeline de visão computacional extrai o círculo branco.
    \item O módulo de rastreamento determina sua posição relativa.
    \item O controlador calcula velocidades para as rodas.
    \item A ponte H recebe o comando e o robô ajusta sua direção.
    \item O ciclo se repete enquanto houver alvo detectado.
\end{enumerate}

Este ciclo caracteriza o comportamento dinâmico do sistema e fundamenta a modelagem arquitetural apresentada no capítulo seguinte.
